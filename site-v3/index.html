How the policy gate works

There is no off-chain approver and no trusted server. When the agent key calls agentSpend, the contract itself enforces the policy before a single wei moves:

01Agent only
Only the registered agent key can request a spend — and only the owner can change that key.
02Allowlist
The recipient must be on the owner-managed allowlist. Strangers get nothing.
03Caps
Amount must fit the per-transaction cap and what is left of the daily cap.
04Freeze switch
If the vault is frozen, every agent spend reverts until the owner unfreezes it.
Policy lives in the contract
Rules the agent can never break
Owner-only controls. Policy, allowlist, agent key, freeze and withdrawals are owner functions. The agent key holds none of them.
Owner escape hatch. The owner can withdraw at any time, even while the vault is frozen.
Full audit trail. Every spend, policy change and freeze emits an on-chain event.
